# ADR-001: Встроенный JDK HttpServer, виртуальные потоки и OpenJDK 25 LTS

## Статус
Принято (обновлено 2026-11-24)

## Контекст
Для микросервиса классификации отзывов (Вариант 1, нагрузка до 30 RPS, целевой latency p95 <= 100 мс) требуется лёгкий, отказоустойчивый HTTP-сервер с минимальной поверхностью уязвимостей и без смешения бизнес-логики с фреймворком. В исходном прототипе (`legacy/ReviewClassifier.java`) смешивались консоль, `Scanner` и `FileWriter` в одном классе.

## Решение
1. Использовать **OpenJDK 25 LTS** (актуальный LTS с длительной поддержкой безопасности и стабильными Virtual Threads).
2. Использовать встроенный в JDK `com.sun.net.httpserver.HttpServer` в паре с `Executors.newVirtualThreadPerTaskExecutor()` и строгим Jackson (отключены implicit coercions, включены `FAIL_ON_UNKNOWN_PROPERTIES` и `FAIL_ON_TRAILING_TOKENS`) вместо тяжёлых веб-фреймворков.
3. Применить строго 4-слойную Clean / Hexagonal архитектуру с ручным DI (`ApplicationWiring`).
4. Ограничить размер тела запроса (`65 536` байт), число одновременных запросов (`MAX_CONCURRENT_REQUESTS`, по умолчанию `128`) и время чтения/ответа `sun.net.httpserver.maxReqTime` / `maxRspTime` (`HTTP_MAX_REQ_TIME_SECONDS`, по умолчанию `10` с). Защита от атак уровня slowloris на границе кластера делегируется reverse proxy (Nginx / Ingress / Envoy).

## Последствия
- Минимальный граф зависимостей, быстрый холодный старт и чистая изоляция `domain`/`application`.
- Ошибки десериализации возвращают безопасные диагностические сообщения без отражения исходных пользовательских значений и имён неизвестных полей.
