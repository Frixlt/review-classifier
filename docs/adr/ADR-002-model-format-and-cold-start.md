# ADR-002: Формат словаря модели (JSON + SHA-256), лимиты старта и область v1.0

## Статус
Принято (обновлено 2026-11-24)

## Контекст
Использование `java.io.ObjectInputStream` на недоверенных артефактах несёт критический риск RCE (CWE-502). По `FR-14`, `NFR-09`, `AC-22` и `AC-23` при повреждённом файле модели сервис должен сигнализировать о неготовности, не падая бесшумно, а загрузка словаря не должна превышать 10 секунд.

## Решение
1. Хранить веса модели в детерминированном формате JSON (`data/sentiment_v1.json`) со строгой проверкой SHA-256 (`MessageDigest.isEqual`).
2. Полностью запретить `ObjectInputStream` в production-коде (проверяется SpotBugs).
3. Проверять размер файла (`<= 10 МБ`), непустые ключи, конечные значения весов (`Double.isFinite`) и бюджет времени загрузки (`MODEL_LOAD_TIMEOUT_MS`, по умолчанию `10 000` мс).
4. При сбое холодного старта логировать `ModelLoadException`, оставлять HTTP-сервер запущенным для `/health/live` (`200 UP`), а `/health/ready` и `/api/v1/reviews/classify` отдавать `503 Service Unavailable` (`AC-23`).
5. **Область v1.0 vs v1.1:** автоматическое горячее перечитывание файла модели без рестарта из `UC-03` отложено в v1.1; в v1.0 обновление словаря выполняется через безопасный rolling restart реплик с проверкой `/health/ready`.

## Последствия
- Полное устранение RCE через Java-десериализацию и предсказуемое время холодного старта.
